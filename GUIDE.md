# Как устроен этот проект — объяснение для новичка

Этот документ написан для человека, который вообще не пишет код. Если что-то
непонятно — это нормально, тут всё объясняется с нуля.

## Что это вообще такое

Один файл — **`index.html`** — это вся страница целиком: и внешний вид, и
поведение. Открой его двойным кликом в любом браузере (Chrome, Edge...) — он
заработает прямо с диска, интернет не нужен, кроме загрузки шрифтов.

Живая версия (та же самая страница, но на публичной ссылке):
https://claude.ai/artifact/32rBmgnDika9GmLjiVZfX5

Репозиторий на GitHub (это как "облачная папка с историей изменений" для кода):
https://github.com/dima02551/ink-atlas

## Три языка внутри одного файла

Сайты почти всегда состоят из трёх частей, и все три лежат прямо в `index.html`:

1. **HTML** — "скелет" страницы: какие блоки вообще есть (заголовок, кнопки,
   карточки). В файле это обычный текст с тегами вроде `<div>`, `<button>`,
   `<h1>`. Он идёт первым, без обёртки — так устроена эта конкретная страница.
2. **CSS** — "внешний вид": цвета, шрифты, отступы, круглые уголки. Весь CSS
   лежит внутри тега `<style> ... </style>` в начале файла. Каждая строка вида
   `.card { ... }` — это правило "как должен выглядеть элемент с классом card".
3. **JavaScript (JS)** — "поведение": что происходит при клике, вводе текста,
   выборе города. Весь JS лежит в самом конце файла, внутри тега
   `<script> ... </script>`. Это единственная часть, которую можно назвать
   "программированием" в привычном смысле — она реагирует на действия
   человека и решает, что показать.

Кода на CSS и HTML — большинство файла, но они просто "рисуют" элементы.
Логика — вся в блоке `<script>`, и именно её стоит читать, если интересно
"как это работает".

## Что делает JS-код (по шагам, сверху вниз)

Прямо в файле `index.html`, в блоке `<script>`, каждая функция теперь
подписана комментарием на русском — что она делает и зачем. Коротко, что там
происходит по порядку:

1. **STYLE_ICON, CITIES, MASTERS** — это данные. `MASTERS` — теперь настоящий
   список мастеров, разобранный из реальных постов канала @tattoo_prices (см.
   раздел "Откуда берутся данные" ниже) — не выдумка, а снимок канала на
   момент последнего запуска скрипта-скрейпера.
2. **state** — одна "коробочка", где хранится всё, что сейчас выбрал
   человек: какой город, какие фильтры включены, что введено в поиск. Вся
   страница всегда перерисовывается на основе этой коробочки — данные нигде
   не дублируются и не расходятся друг с другом.
3. **buildCityPills() / buildStyleChips()** — рисуют кнопки городов и чипы
   стилей один раз при загрузке страницы.
4. **filtered()** — берёт весь список мастеров и оставляет только тех, кто
   подходит под текущие фильтры (город, цена, стиль, поиск), затем
   сортирует. Это "мозг" фильтрации — все остальные функции просто
   отображают то, что она вернула.
5. **renderGrid()** — рисует карточки мастеров под картой.
6. **renderMap()** — рисует саму карту: сначала точки городов, а после клика
   на город — точки конкретных мастеров внутри него.
7. **highlightCard()** — когда кликаешь на точку мастера на карте, эта
   функция находит его карточку внизу и подсвечивает её красной рамкой.
8. В самом низу — **подписки на события**: "если человек кликнул кнопку X —
   вызови функцию Y". Именно так страница реагирует на клики, не перезагружая
   саму себя.

## Откуда берутся данные

Два отдельных скрипта в папке `scripts/` (запускаются вручную, не при
открытии страницы):

1. **`scripts/scrape.js`** (команда `npm run scrape`) — заходит на публичную
   веб-версию канала (`t.me/s/tattoo_prices`), листает её назад по постам
   (без логина, без API-ключей — просто обычные HTTP-запросы, как у браузера)
   и для каждого поста пытается вытащить: цену, город (по значку 📍), ссылку
   на мастера (по значку 🚀 или просто первую ссылку в посте) и имя. Формат
   постов у канала не строгий (то "12000", то "от 4.000₽", то "Сеанс 30 000₽"),
   поэтому скрипт — это набор эвристик (шаблонов), а не идеальный разбор.
   Результат раскладывается в `data/`:
   - `data/raw-posts.json` — вообще все посты как есть, без обработки;
   - `data/masters.json` — посты, которые разобрались уверенно (есть и цена,
     и знакомый город, и ссылка) — именно они попадают на сайт;
   - `data/needs-review.json` — посты, которые скрипт не смог уверенно
     разобрать, с причиной для каждого (например "цена не распознана").
     Такие мастера на сайт не попадают, но и не теряются — лежат в этом файле.
2. **`scripts/build.js`** (команда `npm run build`) — берёт готовый
   `data/masters.json` и вставляет его прямо внутрь `index.html`, в тег
   `<script type="application/json" id="masters-data">`. После этого
   `index.html` снова один самодостаточный файл — так и должно быть, чтобы
   двойной клик по нему продолжал работать без сервера.

Чтобы обновить данные на более свежие посты: `npm run scrape`, затем
`npm run build`. Само по себе ничего не обновляется — это разовый снимок.

- **Карта** — не настоящая географическая карта (без реальных улиц и
  координат GPS), а условная схема: точки городов расставлены "на глаз", но
  примерно повторяют реальную географию (запад→восток, север→юг), а точки
  мастеров внутри города — уже полностью случайные. Просто чтобы показать
  идею "выбрал город → увидел мастеров рядом".
- **Ссылка "Профиль мастера"** теперь настоящая — это то, что мастер сам
  указал в посте (Telegram или Instagram). Рядом всегда есть вторая ссылка
  "Исходный пост в канале" — чтобы свериться с оригиналом, если разбор
  выглядит подозрительно.
- **Рейтинга у мастеров нет** — в реальных постах канала никакого рейтинга
  не было, поэтому вместо звёздочки на карточке теперь дата поста ("2 дня
  назад" и т.п.) — выдумывать цифру рейтинга специально не стали.

## Как поправить мастера вручную

Два варианта:

- **На один раз, быстро**: открой `index.html`, найди
  `<script type="application/json" id="masters-data">` — внутри лежит весь
  список мастеров одной строкой JSON. Найти нужного (поиском по имени),
  поправить значение, сохранить файл. При следующем `npm run build` это
  правило сотрётся (перезапишется из `data/masters.json`), так что это
  вариант именно "на один раз".
- **Навсегда**: сначала так же поправь `data/masters.json` (он читаемый,
  с отступами), затем `npm run build` — изменение попадёт в `index.html`
  и переживёт следующий запуск скрейпера, пока не тронешь эту запись снова.

Поля мастера: `id` (число, у всех разное), `city` (ключ из `CITIES` в
`index.html`, например `msk`, `spb`, `kzn`), `district`, `name`, `styles`
(список из `STYLE_ICON`), `price` (число, без пробелов), `link` (ссылка на
мастера), `sourcePost` (ссылка на исходный пост), `date` (ISO-дата), `x`/`y`
(0-100, положение точки на карте внутри города).

## Что можно улучшить дальше

1. **Разбор постов ещё точнее** — сейчас скрипт уверенно разбирает ~370 из
   455 последних постов (остальные — в `data/needs-review.json`: то нет цены
   в узнаваемом формате, то город не из списка известных). Можно донастроить
   правила (`scripts/scrape.js`, функции `parsePrice`/`parseCity`) под новые
   форматы, которые там встречаются.
2. **Вся история канала** — сейчас берутся последние ~450 постов
   (`TARGET_COUNT` в `scripts/scrape.js`). Канал целиком — это уже тысячи
   запросов к t.me, дольше и с риском, что Telegram начнёт ограничивать
   частые запросы.
3. **Регулярное обновление** — сейчас данные обновляются только когда кто-то
   вручную запускает `npm run scrape && npm run build`. Для реального продукта
   это стоит делать по расписанию (например, раз в день).
4. **Настоящая карта** — если понадобятся реальные координаты города/района,
   потребуется сервис геокодирования (превращает адрес в координаты).
5. **Публикация сайта на постоянный адрес** — например, через GitHub Pages
   (бесплатный хостинг прямо из этого репозитория) или на отдельном домене.

## Структура репозитория

```
ink-atlas/
├── index.html            — вся страница: HTML + CSS + JS + данные мастеров одним файлом
├── GUIDE.md              — этот документ
├── package.json           — список npm-команд (scrape, build) и зависимостей
├── scripts/
│   ├── scrape.js          — тянет посты из канала и раскладывает по data/*.json
│   └── build.js           — вставляет data/masters.json внутрь index.html
└── data/
    ├── raw-posts.json     — все собранные посты как есть
    ├── masters.json        — посты, разобранные уверенно (то, что видно на сайте)
    └── needs-review.json  — посты, которые скрипт не смог разобрать, с причиной
```
